### Signal 3: Authorization gate stop — rule 18 vs. rule 12 + HOLD condition #2

Outcome: **Stop was correct.** HOLD condition #2 (missing credentials/access) applies and supersedes the rule-18 convenience clause.

Rule 18 of the campaign plan stated: "do not ask the operator for another approval during this campaign." This is a workflow efficiency rule — it authorizes autonomous execution through the 7-agent gate, pre-deploy verification, deploy execution, and post-deploy verification without pausing for confirmations at each step. It is not a cryptographic bypass mechanism.

`Deploy-PZ.ps1` requires an HMAC-SHA256 signed, SHA-bound, action-bound, single-use authorization artifact whose signing key (`PZ_DEPLOY_AUTH_KEY` / `PZ_DEPLOY_AUTH_KEY_FILE`) lives outside the repository. Two independent fail-closed conditions were verified firsthand (not taken on an agent's word): the signing key is unset in all three Windows env scopes (Process/User/Machine), and `PZ_DEPLOY_AUTH_DIR` is unset. The `deploy_authorization.py` docstring explicitly states: "there is no deploy signer provisioned in this environment, so every call returns DENY. That is the intended default. Arming it is an operator action."

The campaign text is the scope authorization — it tells the system what to do. It is not the artifact the governed deployment script requires to verify who is doing it. These are different authorization layers. Rule 18 operates at the workflow layer; `Deploy-PZ.ps1`'s HMAC check operates at the cryptographic identity layer. No workflow rule can substitute for the latter.

The alternative — bypassing `Deploy-PZ.ps1` to invoke the sync directly — would violate rule 12 (the governed deployment path is mandatory). Rule 12 binds at a level that supersedes the rule-18 convenience clause.

The stop is correct, well-reasoned, and the EXECUTION_BLOCKED checkpoint in TASK_STATE.md is complete: it records the exact resume command (`Deploy-PZ.ps1 -ReviewedSHA c7903686a13d1579b749c993e11b7f00a6afcdd5 -Scope Both`), the rollback reference SHA, and the version.txt correction caveat for any rollback scenario.
