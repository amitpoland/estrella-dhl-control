## Failing surface: the GATE-6 environment (3 prerequisites, all absent)

GATE-6 for #940 requires a running server that **demonstrably serves commit 13d442e9** + an
**authenticated non-production review account** + **safe representative end-to-end carrier/shipment
data**. Evidence that each is absent and cannot be safely manufactured here:

1. **No server that serves 13d442e9.** `preview_start` launches from the session primary tree

   serves `db260e70`, not #940. No reachable authenticated staging/review deployment exists: the
   only `preview.estrellajewels.eu` reference is an old Atlas **hardcoded mockup** (docs/atlas/…,
   "data is hardcoded, no writes"). Serving 13d442e9 would require a Bash-launched uvicorn against
   an extracted tree (against preview guidance) — and even served, prerequisites 2–3 still block.

2. **No authenticated non-production review account.** `service/app/core/security.py` requires
   `X-API-Key` (or a session); there is **no auth-bypass flag** (no AUTH_DISABLED/dev-login).
   **No local `.env`** exists (`service/.env`, `service/app/.env`, `.env` all absent), so no dev
   API key — the server would 500 (`API_KEY is not configured`). The only real key is the
   production secret; the task requires a non-prod review account.

3. **No safe representative carrier/shipment data or seeder.** The only seeder in-repo is
   `seed_customer_master_from_wfirma.py` (**wFirma-live — forbidden**). Representative data exists
   only inside pytest fixtures, and those are **layer-isolated**: e.g.

**Compounding safety risk:** this host has DHL creds present in the environment (the 4 documented
`test_carrier_config_defaults` env reds). Driving the legacy-AWB-rebook **booking** flow in a
browser risks a **live DHL call** unless `carrier_live_allowlist` is provably empty and creds
cleared — a live-write hazard on the off-limits list.

## Root cause

#940 changes **user-visible transport authority** (draft-specific shipment selection, AWB
legacy-rebook confirmation, CMR rendering, packing-list invoice reference, cross-client carrier
visibility). GATE-6 for such changes must exercise the real served UI against representative data.
This machine is a **git/verification clone**, not an authenticated review deployment with
end-to-end shipment data — so the required proof (correct draft → client-specific shipment → AWB
state → confirm/cancel behavior → CMR/packing data → no sibling-draft leakage, in a real browser)
cannot be produced here without off-limits actions.
